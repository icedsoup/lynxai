# Project instructions

## Keep the project plan current

Automatically update `plan.md` whenever project work changes anything described in it, without waiting for a separate request. Make the relevant plan updates as part of the same task, including changes to implemented capabilities, architecture, interfaces, decisions, backlog items, milestone status, and validation evidence.

Keep the plan factual: distinguish proposed work from implemented and validated behavior, record limitations and blockers, and only mark milestone acceptance criteria complete when supporting evidence exists. Preserve unrelated plan content and do not invent results or silently weaken acceptance criteria.

## Keep the README current before publishing to main

Whenever code is committed for and pushed to `main`, review `README.md` and update it if the changes affect its accuracy or completeness. Include any necessary README updates in the same change before pushing, without waiting for a separate request. Cover changes to project status, implemented features, setup, dependencies, commands, usage, and limitations. If the README already reflects the change accurately, leave it unchanged. Describe only implemented capabilities and supported validation evidence.
